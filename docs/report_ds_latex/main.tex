Flights/Accidents (>200k records) caused KNN bottlenecks. High missing value density in Accidents vs. complete Traffic suggests imputation is more critical for the former.

Accidents feature space is dominated by categorical indicators (70\%), unlike the mixed-type Flight dataset. Imbalance in target variables ($CANCELLED < 5\%$) suggests standard accuracy will be misleading, pointing towards F1-score as a primary evaluation metric.

Maintaining high temporal resolution is vital; daily aggregation would mask intra-day variance critical for predicting short-notice classification events like cancellations or crash severity.

\subsection*{\textit{Data Sparsity}}
One-Hot encoding of airline and airport codes in Flights leads to a high-dimensional sparse matrix (over 300 binary features). This sparsity negatively impacts distance-based models like KNN, which suffer from the curse of dimensionality where points become equidistant. Correlation analysis reveals significant redundancy between spatial features (e.g., Origin and Destination city pairs in Flights), suggesting that feature selection is required to improve learner efficiency.

\section{DATA PREPARATION}

\subsection*{\textit{Variables Encoding}}

Variables not mentioned were dropped over redundancy and data leakage.\\

\textbf{Traffic Dataset}

\textbf{Ordinal Encodings (1 = low, 4 = high):} Weather conditions; Lighting conditions; Trafficway type; Roadway surface condition; Road defects. Categories were collapsed to four levels based on a approximate perception of crash risk.

\textbf{Binary encoding:} Intersection-related variable.

\textbf{Hot-encoding:} traffic control device related variables.


\textbf{Cyclical temporal encoding:}
\texttt{crash\_hour\_sin}, \texttt{crash\_hour\_cos};
\texttt{crash\_day\_sin}, \texttt{crash\_day\_cos};
 \texttt{crash\_month\_sin}, \texttt{crash\_month\_cos}.
Original variables dropped.\\

\textbf{Flights Dataset}

\texttt{Distance} was left unchanged.

\textbf{Hot-encoding:}
\texttt{OriginStateName} and \texttt{DestStateName}retained in their original form, as alternative encodings degraded performance. Same for non reduntant Airline variables.

\textbf{Cyclical temporal encoding:}
\texttt{CRSDepTime\_sin}, \texttt{CRSDepTime\_cos};
 \texttt{CRSArrTime\_sin}, \texttt{CRSArrTime\_cos};
 \texttt{DayOfWeek\_sin}, \texttt{DayOfWeek\_cos};
\texttt{Month\_sin}, \texttt{Month\_cos}.
Original variables dropped.






\subsection*{\textit{Missing Value Imputation}}
Two missing value imputation strategies were evaluated: frequent-value and KNN imputation. Each method assessed using the F1. F1 score used is from KNN and NB reference models.\\

\textbf{Traffic Dataset}

Frequent-value imputation achieved an average F1 score of 0.8553 across models, while KNN imputation achieved 0.8555. We  \textbf{proceed with KNN imputation} for subsequent analyses.\\

\textbf{Flights Dataset}

Process skipped. The dataset was too large and unbalanced. Creation of a smaller balanced sample was required for data preparation. Missing values were not introduced in the sample.

\subsection*{\textit{Outliers Treatment}}

Outlier treatment approaches: IQR with a 1.5 threshold and a more conservative 3-standard-deviation ($3\sigma$) method. The standard deviation method was applied only if a record had over two outlier features. Anomalies may help define classes.\\


\textbf{Traffic dataset}
IQR 1.5 yielded an average F1 score of 0.8632, while $3\sigma$ achieved an average of 0.8558. \textbf{IQR 1.5 method was selected}.\\

\textbf{Flights dataset}
IQR 1.5 yielded an average F1 score of 0.4023, while the $3\sigma$ achieved an average of 0.4117. The \textbf{Standard-Deviation method was selected}.

\section{MODELS' EVALUATION}
{All models were trained on data prepared in previous stages (encoding, mvi, outlier treatment, scaling, balancing, feature selection). A stratified 70/30 train-test split was used. Five metrics assessed performance: accuracy, precision, recall, F1-score, and AUC. Both training and test set performance were covered for most models to identify overfitting across hyperparameter configurations.}

\subsection*{\textit{Na{\"i}ve Bayes}}
{Tested GaussianNB and BernoulliNB estimators. Both made identical predictions: different probabilistic models yielded equivalent decision boundaries on preprocessed data. GaussianNB selected (could have selected either one) as best by accuracy: 0.82 for accidents dataset and 0.97 for flights.}

As k increased, training accuracy decreased while test performance stabilized.}

\section{CRITICAL ANALYSIS}
{All models achieved strong performance on accidents dataset (in terms of accuracy and f1 measures) with balanced predictions across both classes. However, flights dataset showed how important balancing is: despite 0.97 accuracy, all models except KNN predicted only the majority class (KNN detected minimal minority instances, F1=0.04). Flights dataset was extremely imbalanced (365 True, 11870 False: 3\% minority). Data preparation significantly changed results: encoding transformed categorical variables into numerical format, enabling sklearn algorithms to run; scaling (0-1 normalization) was essential for KNN where unscaled features would dominate distance calculations. At the same time, balancing techniques proved insufficient for flights dataset, where extreme class imbalance persisted, causing most models to mistakenly predict the majority class. Variable importance analysis revealed consensus across tree-based models: injuries\_total ranked highest for accidents (root node, top in RF/GB), while Month and DayofMonth emerged as key predictors for flights. For accidents, all models produced nearly identical confusion matrices with similar error distributions. For flights, all models except KNN generated identical failure patterns (11870 True Negatives, 365 False Negatives, 0 True Positives), indicating systematic majority-class prediction. Simple models (Naive Bayes) and complex models (Random Forests, Gradient Boosting, MLPs) achieved comparable accuracy levels, suggesting decision boundaries are not highly non-linear. This consistent performance across diverse model families validates that data characteristics, rather than model architecture choice, fundamentally drive classification results. Based on the results obtained, the best models perform well at predicting crash\_type but fail at predicting cancelled. Even though they predict accurately when a flight is not cancelled, they cannot predict when it is, which is the most impactful situation for a passenger.}

\subsection*{\textit{LSTMs Model}}
Traffic LSTM with sequence\_length=24 (daily cycle), hidden=32, epochs=900 achieved train R²=0.92, test R²=0.68, RMSE=0.05. Lookback=24 hours optimal for capturing intra-day patterns. Model shows overfitting (24\% R² drop) but maintains consistent RMSE. Forecasts capture volatility better than ARIMA. Economic LSTM failed catastrophically: train MAPE=100\%, test R²=1.0 (likely numerical error). With only 14 yearly observations, lookback=2 minimized MAE$\approx$0.90, but insufficient data prevented meaningful temporal learning. LSTM architecture [2 layers, 8 neurons] unable to generalize from sparse samples.

\section{CRITICAL ANALYSIS}
LSTM provided the best model for traffic forecasting. The model was best when a sequence of 48. The advantages of this sequence are two. First, this sequence allows for the identifying of seasonality, the daily routines of the populus. Second, it allows to identify the trend of the data, the increasing or decreasing traffic activity from day to day. The main drawback is the tendency of the model to overfit. The best result is attained for 32 hidden units, the model attains its best result, but if one wishes to reduce the likelihood of overfitting, 8 hidden units gives a sufficiently capable system. The group considers the model reliable for the task.

Regarding the remaining methods such as MLP, ARIMA and Exponential Smoothing, MLP lacks LSTM recurrent structure, whilst ARIMA and Exponential Smoothing are better suited for more linear data. ARIMA and Exponential Smoothing also present challenges in terms of data preparation; applying differentiation and smoothing in data that was already prepared.
The Economic Dataset was far harder to handle.

Inflation is a mixture of politics and economics; it might as well be witchcraft. On top of the theoretical challenges of the problem domain (chaotic behavior of markets, political machinations of the practical and ideological kind, black swan events, etc) there’s also practical challenges. Very little data is available. Sometimes inflation data is not reported for long periods of time. Patterns become hard to establish. We have data from other countries, but with so little American data, it probably just adds noise. Ideally we would have more data, perhaps the addition of raw gas price data would useful. The best model appears to be ARIMA, but none of the models appears remotely reliable enough.
